# Production deployment checklist

This project fails closed when `DJANGO_ENV=production`: it requires a strong secret key,
explicit hosts, MySQL credentials, an SMTP host, and the isolated code-runner URL/token.

## 1. Prepare environment variables

Copy `.env.production.example` to the deployment environment's secret store. If a local
`.env.production` file is used, it is ignored by Git but is not loaded automatically; load it in
the service environment or copy its values into the ignored `.env` file.

Generate a secret key and store the output as `SECRET_KEY`:

```powershell
.\venv\Scripts\python.exe -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

Use a dedicated MySQL account limited to the application database. Do not use `root`. Configure
TLS at the reverse proxy, and only set `DJANGO_TRUST_PROXY_HEADERS=true` when that proxy overwrites
and validates `X-Forwarded-Proto`.

## 2. Validate and build

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe manage.py check --deploy
.\venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\venv\Scripts\python.exe manage.py migrate --noinput
.\venv\Scripts\python.exe manage.py collectstatic --noinput
```

Do not deploy if `check --deploy` reports an error or warning that has not been consciously
reviewed. Start with `DJANGO_SECURE_HSTS_SECONDS=3600`; increase it only after HTTPS is verified.
Enable HSTS preload only after every subdomain is permanently HTTPS-capable.

## 3. Run on Windows

Django's development server is not a production server. On Windows, run the WSGI application with
Waitress behind a TLS reverse proxy:

```powershell
.\venv\Scripts\waitress-serve.exe --listen=127.0.0.1:8000 config.wsgi:application
```

The reverse proxy should be the only public listener. WhiteNoise serves versioned static assets
generated by `collectstatic`; the isolated code runner should remain private and must receive no
database, Gemini, or Django secret.

## 4. Test safely

The default test settings use an in-memory SQLite database and never touch the configured MySQL
database:

```powershell
.\venv\Scripts\python.exe manage.py test --settings=config.settings_test
```

Before release, also perform a smoke test against a separate MySQL test database using a dedicated
test account. Never run destructive test commands against the production database.

## 5. Operations

- Back up MySQL and verify restore procedures.
- Rotate database, runner, Gemini, SMTP, and Django secrets.
- Retain application and reverse-proxy logs without logging learner code or credentials.
- Monitor runner timeouts/errors and AI fallback rates.
- Review `/progress/` access rules before adding authenticated multi-user accounts.
